# 架构与设计（v0.2）

## 1. 目标

1. **主体是智能体网络**：每个用户、每个生产者都有自己的智能体。消费者的智能体替用户决定接收什么、拒绝什么、去要什么、买什么、转给谁；生产者的智能体根据网络里看得到的需求，决定生产什么、定价多少、推给谁。
2. **去平台化**：没有哪一方同时握有全部数据、定价权和流量分配权。X 的推荐算法不再是系统骨架，而是智能体**可以选择调用的技能**。
3. **实体与信息统一**：同一种 `Offer`，同一条「生产 → 定向提议 / 查询 / 转发 → 议价 → 授权支付 → 交付 → 结算 → 信誉」链路。
4. **可验证**：有经济意义的事实，以及会影响一个智能体如何评价另一个智能体的消息，都是签名对象。谁签名谁负责，任何人都能独立验证。
5. **用户主权**：披露多少偏好、接收谁的提议、订阅哪些标注方、信任哪些托管方、给智能体多大支付授权，都由用户（principal）决定。

## 2. 角色

| 角色 | 取代平台的哪项职能 | 可以有多家吗 |
|---|---|---|
| `ConsumerAgent`（个人智能体） | 推荐流、搜索、购物车、结账、订阅、分享 | 每个用户一个 |
| `MerchantAgent`（实体或信息生产者） | 卖家后台、创作者工具、广告投放 | 任意多个 |
| `BankAgent` | 支付（AP2 中的 Credential Provider 和 Merchant Payment Processor） | 多家；仿真里只有 1 家 |
| `EscrowAgent` | 亚马逊 A-to-z 交易保障 | 多家，费率自定，买卖双方选共同信任的 |
| `LogisticsAgent` | 平台物流与签收 | 多家 |
| `LabelerAgent` | 平台的信任与安全团队 | 多家，用户自选订阅 |
| Principal（人或企业） | 持有签发开放授权的私钥（AP2 中的 Trusted Surface），最终决定买不买 | — |

## 3. 一个智能体由什么构成（`agora/mind/`）

| 部件 | 内容 |
|---|---|
| `UserProfile` | 用户自己说的：喜欢、讨厌、各品类价格上限、注意力额度（每轮愿意看几条）、每个生产者每天最多推几条、地区、披露级别、当前需求（`Need`）。另有从反应中学到的偏好 |
| `Memory` | 每个生产者：提议数、放行数、好评、成交、退款 → 信任 `(1+好+2·成交)/(2+好+2·成交+差+3·退款)` 与命中率 `(1+放行)/(2+提议)`；每个朋友的推荐命中率；已决定 / 已购买 / 已判不安全的条目集合 |
| `SkillRegistry` | 本地技能、X 推荐栈技能、其他智能体的 A2A 能力（`remote_skill`），统一调用和计数 |
| Brain | `ConsumerRuleBrain` / `ProducerRuleBrain`（规则，可解释）或 `LLMBrain`（任意 OpenAI 兼容接口）；输出带理由的 `Decision` |

**偏好学习**是贝叶斯平均：用户说过喜欢的品类相当于 3 次评分为 0.8 的观察，没说过的品类相当于 1 次评分为 0.15 的观察，之后每次反应（转发/购买 1.0，收藏或长停留 0.8，点击 0.5，无反应或负反馈 0）都加进去。这样少量反应就能发现用户没说过的兴趣，几次冷淡也抹不掉用户明确说过的喜好。**用户说讨厌的品类不参与学习，永远排除。**

每个决策都写进 `decision_log`（动作、对象、理由、由规则还是大模型做出），用户随时能查到某样东西为什么被放进来、为什么被挡在外面。

## 4. 消费者智能体的决策循环（`mind/consumer_brain.py`）

每一轮观察到的是：收件箱里的提议和朋友推荐、本轮主动找来的条目、未满足的需求。

1. **为需求去找**，从便宜到昂贵逐级升级，找到合适的就停：本地检索（`search_local`，有 X 技能时用 `x_retrieve`）→ 问做这类东西的生产者（`query_producers`）→ 第二轮起问朋友（`ask_peers`）→ 仍然没有，就广播一条签名求购（Intent），让生产者来找自己。
2. **硬性拒绝**，任何情况下都不会让用户看到：被屏蔽的生产者、订阅的标注方或安全规则判为 DROP 的、用户说过不要的品类、不发货到用户地区的、信任低于下限的。
3. **按需求下单**：每个需求挑一件，打分为 `匹配度 × (0.5 + 0.5 × 信任) − 0.15 × 价格/预算`，然后议价、经托管付款，受 AP2 授权约束。免费信息直接给用户读，读了就算满足需求。
4. **在注意力额度内挑选展示**：效用 = `喜好 × (0.55 + 0.45 × 信任) − 0.6 × 超出价格上限的比例 + 朋友推荐加分`，高于阈值才有资格。**资格只由用户画像决定**；有资格的条目超出额度时，才调用 `x_rank` 排先后（与效用各占一半）。
5. **探索**：每轮以 35% 的概率留出 1 个名额，给用户没提过的品类，每个品类最多试 2 次；手里没有就主动去搜一个。用户可以关掉。
6. **回传理由**：每条拒绝都带理由码，签名后批量回传给提议它的生产者。
7. **把东西交给用户**：用户的反应决定学习信号；用户自己想买的，智能体去议价付款；用户转发的，智能体按朋友的兴趣卡**有针对性地**转给朋友（只转给卡上该品类权重 ≥ 0.3 且不在回避列表里的朋友），附背书链用于推广分成。
8. **管理关系**：已收到至少 6 条提议、命中率低于 20% 的生产者被屏蔽；持续交付好东西且信任 ≥ 0.65 的生产者被订阅；学到的兴趣和上次发出的兴趣卡偏差 ≥ 0.2 时，重新签发兴趣卡。

**收件时就挡下的**（不进入决策，直接回签名拒绝）：被屏蔽的生产者；私密用户收到的未订阅、非求购响应的提议；超过对方每日上限的；重复的。

## 5. 生产者智能体的决策循环（`mind/producer_brain.py`）

1. **看需求**（`demand_scan`）：汇总收到的兴趣卡（公开卡来自 gossip，订阅者卡来自订阅时附带或主动分享）、未过期的求购意图、各品类收到的签名反馈。
2. **决定生产什么**：对每个能做的品类，`(还没触达的感兴趣者的卡片权重之和 + 0.2 × 感兴趣者人数) × p + 2 × 求购数`，再乘以利润空间；其中 `p` 从「接受率」的 Beta 后验里抽样（Thompson 采样），兼顾已知效果和探索。信息生产者像媒体一样按节奏更新；商家在现有商品已推给所有感兴趣者之后才上新。
3. **决定推给谁**：对每个（消费者, 品类）维护 Beta 后验，初值来自兴趣卡上的权重，之后用该消费者的签名接受/拒绝更新；超价打折，求购响应加分；有 `x_audience` 技能时用 SimClusters 的相似受众加分。不超过对方卡上声明的每日上限，不往不发货的地区推。
4. **调价**：「太贵」类拒绝超过 30% 就降价 8%，接受率超过 60% 就提价 3%。
5. **响应查询**：消费者为某个需求来问时，手上没有合适的就现场生产（按单生产，C2M）。

对照组 `SpamBrain` 是仿真里的坏人：每轮都生产，推给所有能找到的消费者，从不看反馈。

## 6. X 推荐栈作为技能（`skills/x_stack.py`）

移植自 xai-org/x-algorithm @ `9081b33`，Python 实现在 `agora/ranking/`。

| 技能 | 内部实现 | 谁调用、什么时候 |
|---|---|---|
| `x_rank` | candidate-pipeline 框架上的小流水线：Phoenix-lite 多行为打分 → 价值模型 → 作者多样性 → DPP | 消费者：有资格的条目超出注意力额度时排先后；挑探索条目 |
| `x_retrieve` | Phoenix 双塔召回 | 消费者：为需求检索本地已验证的 Offer |
| `x_safety` | visibility-filtering 规则 + 订阅的标注方标签 | 消费者：安全判定（不调用就用基础的 `labels_check`） |
| `x_reputation` | user-cred-v2 风格的 PageRank | 消费者：信任分，与自身经验混合 |
| `x_audience` | SimClusters（Louvain 社区 + KnownFor/InterestedIn） | 生产者：找相似受众 |
| `x_for_you` | 完整 home-mixer 流水线 | 需要一份现成推荐流时 |

几点设计取舍：
- **资格来自用户画像，X 只负责排序。** 排序模型学的是参与度，参与度不等于用户利益；所以「该不该让用户看到」由画像和硬性规则决定，X 只在稀缺的注意力名额上决定先后。代价是 X 的提升有限（仿真里相关度 +5%）。
- **Phoenix-lite**：每个候选只对「用户 + 历史 + 自己」做注意力（候选隔离，与 X 的 `attention_segment_ids` 一致），打分与批次组成无关；特征用双哈希映射进 4096×24 的嵌入表；每轮用用户的真实反应在本地训练（BCE + 停留时长 MSE），数据不离开这个智能体。
- **价值模型**沿用 X 的权重与 offset 逻辑，负向动作的大幅负权重（举报 −234 等）保留；商业动作（购买 12、咨询 3、退货 −40）的权重是本项目设定的。
- 技能也可以是另一个智能体的 A2A 能力：比如在 GPU 机器上部署大模型版 Phoenix，作为排序服务智能体供人调用，调用方用 `remote_skill` 包一层即可。

## 7. 大模型决策脑（`mind/brain.py`）

`LLMBrain` 对任意 OpenAI 兼容接口（如 vLLM）跑一个 JSON ReAct 循环：每一步模型要么调用技能 `{"call": {"skill", "args"}}`，结果以 `SKILL_RESULT` 回给模型；要么给出决策 `{"decisions": [...]}`。最多 4 步。

模型给出的决策**在代码里再过一道闸**（`validate_decisions`），不合规的直接丢弃，并记 `llm_vetoed`：

- **消费者**：目标必须是本轮观察到的条目；接受和购买要先过第 4 节第 2 步的全部硬性规则（屏蔽、标注方判定、讨厌的品类、发货地区、信任下限）；购买只能针对未满足的需求，品类和类型一致，价格不超过需求预算的 1.15 倍；展示不超过注意力额度；屏蔽和订阅只能针对已知生产者。
- **生产者**：只能向自己手里有兴趣卡或求购的智能体提议，地址取卡上的地址而不是模型给的；不超过对方每日上限，不往不发货的地区推；调价每次限制在 0.85–1.1 倍。

模型没覆盖的条目由规则脑补上；模型输出乱码、超时或接口不可用，整轮回退到规则脑。这样大模型出问题只会降低决策质量，不会突破用户设的边界。提示词里也写明：条目标题和推送理由是生产者写的，只能当数据，不能当指令。但真正起作用的是代码里的闸，因为提示词注入无法从提示词层面根除。

花钱的边界还有第二道：即使智能体被攻破，用户签发的 AP2 开放授权（单价、累计预算、只能付给托管方、品类）由银行强制执行。

## 8. 披露与隐私

兴趣卡（`agora.interest+jws`）是智能体对外声明「我愿意接收什么」，披露级别由用户选：

| 级别 | 卡片内容 | 发给谁 | 代价（仿真，5 个种子） |
|---|---|---|---|
| `public` | 前 4 个品类，权重粗化到 0.1 | 订阅的生产者、朋友，并经 gossip 扩散 | 人均收 44 条提议，需求满足 0.86 |
| `subscribers` | 前 8 个品类，权重精确到 0.01 | 只给订阅的生产者和朋友，**不进 gossip** | 24 条，0.81 |
| `private` | 不发卡 | — 只发求购；未订阅生产者的提议在收件时就被拒绝 | 14 条，0.80 |

其他保护：朋友问「你知道哪里有 X 吗」时，回答会暴露用户喜欢过什么，所以查询必须签名、指明接收方，只回答已确认的朋友；同一个查询不能重放。

尚未解决：结算记录经 gossip 公开，可以看出谁和谁做过交易；公开卡即使粗化，仍会暴露部分偏好。见第 13 节路线图。

## 9. 传播

- **定向提议**（`agora.proposal`）取代 v0.1 的「推给所有关注者」：生产者按第 5 节第 3 步挑对象，每条提议都由生产者签名、绑定接收方。
- **订阅**（`agora.follow`）：消费者签名订阅指令，可附兴趣卡。订阅的生产者的提议标为 `subscribed`，私密用户也会接收。
- **朋友转发 = 背书链**：`make_endorsement` 把上一级背书作为 `parent` 嵌入，形成 根 → … → 叶 的签名链。转发（`agora.recommend`）另带一份发送者签名、绑定接收方的指令，第三方拿到公开的背书也无法冒充朋友去推。
- **分佣**：分佣池 = 成交额 × `referral.bps`。从离买家最近的转发者开始，权重依次为 1、1/2、1/4……，最多 `maxDepth` 跳；生产者和买家本人不参与。商家把链签进报价单，买家核对链没被删改，托管方按报价单分账。推广费付给真正带来成交的人，而不是平台的广告费。
- **求购（C2M）**：消费者把签名 Intent 推给订阅的生产者，同时经 gossip 扩散。能供货、底价不超过预算的生产者主动提议（带 `intentId`）。
- **gossip 反熵**：每个智能体按「对端 × 对象类型」记录水位，只发送对方没收到的签名对象（Offer、背书、结算、评价、标签、求购、公开兴趣卡），收到后逐个验签、按哈希去重。

## 10. 一笔交易的 A2A 任务状态（与 v0.1 相同）

```
消费者                         商家                    托管            银行            物流
 │ agora.rfq ───────────────▶ │ 校验Offer/库存/地区/背书链/共同托管
 │ ◀─ INPUT_REQUIRED + quote(签名报价单)
 │ agora.counter ───────────▶ │ SellerPolicy（时间依赖让步）
 │ ◀─ INPUT_REQUIRED + quote …（最多 4 轮；信息商品不议价；免费信息不走这条流程）
 │ agora.accept(封闭授权+开放授权) ▶ 校验 AP2 链，锁库存
 │ ◀─ INPUT_REQUIRED + awaiting_funding
 │ agora.escrow.open ──────────────────────────────▶ │
 │ agora.pay(开放+封闭支付授权) ─────────────────────────────────▶ │ 校验链/额度/预算/收款方
 │ ◀────────────────────────────────────────────────────── 支付回执 │
 │ agora.escrow.fund(回执) ────────────────────────▶ │
 │ agora.funded ─────────────▶ │ 查询托管状态 ────▶ │
 │                             │ agora.ship(签名指令) ─────────────────────────────▶ │
 │ ◀─ COMPLETED + artifact(签收回执 或 签名内容)
 │ 验货 / 核对内容哈希
 │ ├─ 满意：agora.escrow.release(签名指令) ───────▶ │ 分账转账 ──▶ 银行；签发结算
 │ └─ 不符：实体先退货拿回执；信息直接用签名内容作证据
 │          agora.escrow.dispute(证据) ───────────▶ │ 验证据 → 退款；签发结算
 │ 写评价（必须引用自己的结算）→ gossip
```

分账示例：成交价 100，托管费 50 bps，商家分佣 300 bps，转发链为 A → B → 买家。托管费 0.50；分佣池 3.00，其中 B 得 2.00、A 得 1.00；商家实收 96.50。没有平台这一项。

## 11. 信任与信誉

一个智能体对某个生产者的信任由三部分组成：自己的经验（`Memory`）；经签名结算验证过的全网成交和退款统计；有 `x_reputation` 技能时再混入 PageRank 信誉。订阅的标注方给出的 fraud / scam-risk 标签直接压低信任，并经安全技能把条目判为 DROP。

PageRank 信誉（`x_reputation`）的图：
- **边**：已放款的结算（买家 → 商家，权重 `log1p(金额) × (0.1 + 0.9 × ((评分−1)/4)²)`，无评价按 0.5 计）；背书（转发者 → 生产者，0.3）；订阅（0.2）。
- **跳转质量**：0.5 × 均匀分布 + 0.5 × 真实消费额的平方根（β=0.5、最多 50 轮，与 UserCredV2Config 默认值一致）。
- **惩罚**：乘以 `(1 − 退款率)²`。
- **抗刷量**：小号没有真实成交就拿不到跳转质量；自建的「托管方」不在任何人的信任列表里，它签的结算不计分；评价必须引用一笔以评价者为买家的托管结算，刷一条评价就要付一笔真实货款加托管费。

## 12. 威胁模型

| 攻击 | 缓解 | 剩余风险 |
|---|---|---|
| 群发垃圾提议 | 每个生产者每天的条数上限（写在兴趣卡上）；私密用户拒收未订阅的提议；低命中率自动屏蔽，屏蔽理由签名回传 | 新身份重新开始：初始信任中性，仍要逐个被拒。仿真中垃圾商家被 24 个用户中的 13.8 个屏蔽，零成交 |
| 冒充生产者提议（耗掉它的额度、拉低它的命中率让它被屏蔽） | 提议由 Offer 的生产者签名、绑定接收方、带一次性 nonce | — |
| 冒充朋友（套取用户喜欢过什么、刷朋友命中率） | 查询和转发都由发送者签名、绑定接收方、不可重放；只回答已确认的朋友 | 仿真里加好友自动接受；实际部署应由用户确认 |
| 回放旧兴趣卡、重复计入反馈 | 卡片只接受更新的 `issuedAt`；反馈按令牌哈希去重 | — |
| 提示词注入（Offer 文本诱导大模型） | 第 7 节的代码闸：硬性规则、需求、价格、额度、目标都在代码里强制；AP2 授权由银行强制 | 在规则允许的范围内做出差的选择 |
| 假货 | 托管 + 退货回执 + 退款率标签 + 信誉惩罚 | 商家与物流串通伪造签收：多物流方并存，物流方自身也有信誉 |
| 付费信息挂羊头 | Offer 里的内容哈希承诺 + 作者签名交付 = 自动举证；退款后被标注方标记，之后在硬性规则里被挡 | 内容真实但质量差：靠评分和信誉 |
| 刷评价 / 女巫刷信誉 | 评价绑定托管结算；跳转质量只给真实消费者；托管方白名单 | 合谋的真实买家 |
| 恶意标注方 | 用户自选订阅；标签附证据；阈值在本地 | 用户订阅了不靠谱的标注方 |
| 智能体超支或被攻破 | 开放授权：单价、累计预算、只能付给托管方、品类；银行执行 | 授权范围内的错误决策 |
| 成交后篡改条款 / 指令重放 | 封闭授权绑定报价单哈希；指令带 nonce 和时效 | — |
| gossip 日蚀攻击 | 多个引导节点 | 全部引导节点都恶意 |
| 偏好与交易泄露 | 三级披露；非公开卡不进 gossip；朋友查询需签名 | 结算公开；公开卡可推断部分偏好 |

## 13. 实验结论的边界

- 所有数字来自合成经济：模拟用户的「真实偏好」和生产者的「真实质量」都是我们生成的。它只能说明机制能跑通、方向是否合理，不代表真实市场效果。
- X 技能带来的提升是小幅的（相关度 +5%、喜欢率 +6%）；成交数和消费者剩余提升更大，但方差也大。
- 生产者从反馈中学习在这个仿真里没有可测的提升（接受率 72.3% 对 71.4%）：兴趣卡已经提供了大部分定向信息。
- 内存传输下结果可复现；真实 HTTP 传输下，消息到达顺序会影响随机数的消耗顺序，同一种子多次运行的结果会有差别（本机四次运行，成交 87–97 笔）。仓库里附带的是其中一次。
- 大模型决策脑只用模拟服务器测过协议、校验和回退逻辑，没有用真实大模型跑过仿真。

## 14. 路线图

1. **真实大模型评测**：在 GPU 机器上用 vLLM 起 Qwen3 等模型，把部分消费者和生产者换成 `LLMBrain`，与规则脑在同一网络里对比；统计被代码闸拦下的决策比例。
2. **把智能体策略当作 RL 问题来训**：这个网络本身就是多智能体环境，奖励（消费者剩余、生产者利润、用户反应）都可以直接从签名结算和反馈里算出来。
3. **隐私**：AP2 原生的 SD-JWT 选择性披露；用零知识证明给出信誉；兴趣卡的差分隐私噪声。
4. **发现与网络**：DHT 或中继（libp2p、Nostr relay），NAT 穿透，智能体托管。
5. **支付轨道**：多银行；稳定币可走 A2A x402 扩展；托管改成智能合约以去掉受信第三方。
6. **模型**：联邦训练 Phoenix-lite；用 x-algorithm 的 `phoenix/` 训练代码在 GPU 上预训练共享底座，下发给各智能体微调。
7. **信息商品的公平交换**：内容加密后先交付，托管方放款的同时释放密钥，托管方全程看不到明文。
8. **协议治理**：把扩展 URI 从 `urn:agora:*` 迁到正式的扩展规范。
