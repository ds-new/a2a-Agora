# A2A Agora：由智能体构成的去平台化网络，用来生产和消费实体商品与信息

**主体是智能体网络。** 每个用户、每个生产者都有自己的智能体，通过 A2A v1.0 直接通信。智能体根据用户喜欢什么、需要什么，**自己决定**接收什么、拒绝什么、去要什么、买什么、转给谁；生产者的智能体根据网络里的需求，**自己决定**生产什么、定价多少、推给谁。

中间没有平台。X（推特）开源的推荐算法不再是系统的骨架，而是智能体**可以选择调用的技能**。不调用它，智能体照样能独立做判断。

> v0.1 的结构是「X 推荐流水线驱动消费者」。v0.2 把它改成「智能体做决定，X 算法作为技能」。协议层、AP2 支付、托管、标注沿用 v0.1。

## 一个智能体是什么

```
          ┌────────────────────────── 智能体（did:key 身份，A2A v1.0 端点）──────────────────────────┐
观察 ───▶ │  用户画像 UserProfile   用户说的喜好/讨厌/价格上限/当前需求 + 从反应中学到的（贝叶斯平均）  │
          │  记忆 Memory            每个生产者、朋友、品类的历史结果：信任、命中率                      │
          │  技能 SkillRegistry     基础技能 + X 推荐栈技能（可选）+ 其他智能体的 A2A 能力              │
          │  决策脑 Brain           大模型（任意 OpenAI 兼容接口，如 vLLM）或规则；大模型失败即回退规则  │ ───▶ 决策（带理由）
          └──────────────────────────────────────────────────────────────────────────────────────────┘
```

每个决策都带理由，并记入 `decision_log`。用户随时可以查到某样东西为什么被放进来、为什么被挡在外面。

### 消费者智能体每一轮做什么（`mind/consumer_brain.py`）

1. **为需求去找东西**：从便宜的方式开始逐级升级：本地检索 → 问生产者（`agora.query`）→ 问朋友的智能体 → 广播签名求购（Intent）。
2. **硬性拒绝**：被屏蔽的来源、标注方判定不安全的、用户说过不要的品类、不发货到本地区的、信誉太差的。
3. **按需求下单**：为每个需求挑最合适的一件，议价后经托管付款（受 AP2 授权约束）。免费信息直接给用户读，不走付款。
4. **筛选展示**：按用户偏好效用挑选，不超过用户每轮愿意看的条数。条目超出额度时，才调用 X 排序技能决定先后。每轮以 35% 的概率留出一个探索名额，用来发现用户没说过的兴趣，可以关闭。
5. **回传理由**：每条拒绝都附理由码，签名后回传给发送方，理由码包括 off-topic / too-expensive / unsafe / attention-budget 等。
6. **管理关系**：订阅持续交付好东西的生产者，屏蔽推送命中率太低的；把用户喜欢的东西**有针对性地**转给兴趣卡匹配的朋友，背书链用于推广分成；兴趣发生明显变化时，更新并重新分发兴趣卡。

### 生产者智能体每一轮做什么（`mind/producer_brain.py`）

1. **看需求**：汇总兴趣卡、未满足的求购意图和收到的签名反馈（`demand_scan`）。
2. **决定生产**：用 Thompson 采样平衡已知接受率和探索，同时考虑还没触达的感兴趣用户和利润空间。信息生产者像媒体一样保持更新节奏；商家在现有商品已推送给所有感兴趣用户之后才上新。
3. **决定推给谁**：按（用户, 品类）维护 Beta 后验，初值来自兴趣卡上的权重，之后用接受/拒绝反馈更新；不超过对方声明的每日上限。带 X 技能的生产者还可以用 SimClusters 找相似受众。
4. **调价**：「太贵」类的拒绝超过 30% 就降价，接受率高就小幅提价。
5. **响应查询**：手上没有匹配的商品时，可以现场生产（按单生产）。

## X 的推荐算法变成了技能

源码来自 [xai-org/x-algorithm](https://github.com/xai-org/x-algorithm) @ `9081b33`（Apache-2.0），可用 `scripts/fetch_upstream.sh` 按固定版本拉取。

| 技能 | 移植自 | 谁用、用来做什么 |
|---|---|---|
| `x_rank` | Phoenix 多行为排序（候选隔离 + 哈希嵌入）+ value model + 作者多样性 + DPP | 消费者：条目超出注意力额度时排先后；挑探索条目 |
| `x_retrieve` | Phoenix 双塔召回 | 消费者：为某个需求检索本地已验证的 Offer |
| `x_safety` | visibility-filtering 规则 + 标签 | 消费者：安全判定（不用它就用基础的 `labels_check`） |
| `x_reputation` | user-cred-v2 PageRank | 消费者：信任分（与自身经验混合） |
| `x_audience` | SimClusters KnownFor / InterestedIn | 生产者：找相似受众 |
| `x_for_you` | 完整的 home-mixer 流水线 | 想要一份现成推荐流时调用 |

基础技能（不含 X 组件）包括：`match_needs`、`trust`、`labels_check`、`search_local`、`ask_peers`、`query_producers`，以及生产者端的 `demand_scan`。技能也可以是**另一个智能体的 A2A 能力**（`remote_skill`），比如把大模型版 Phoenix 部署在 GPU 机器上，作为排序服务智能体供其他人调用。

## 网络上流动什么

所有对象都是签名的 JWS，详见 `docs/PROTOCOL.md`。

| 消息 | 方向 | 作用 |
|---|---|---|
| `agora.interest`（签名兴趣卡） | 消费者 → 生产者 / 朋友 / gossip | 「我愿意接收什么」。披露级别由用户选：`public`（只给前 4 个品类，权重粗化）、`subscribers`（只给订阅的生产者）、`private`（不发卡，只发求购） |
| `agora.proposal` | 生产者 → 消费者 | 提议，附推送理由；由生产者签名并绑定接收方，第三方无法冒充。消费者每轮批量决定 |
| `agora.feedback`（签名） | 消费者 → 生产者 | 接受/拒绝及理由码；生产者据此学习 |
| `agora.query` | 消费者 → 生产者 / 朋友 | 「我需要 X，你有吗？」签名并绑定接收方；朋友只回答确认过的朋友，回复时附上自己的背书，推广链由此建立 |
| `agora.recommend` | 消费者 → 朋友 | 定向转发，带背书链和发送者签名 |
| `agora.intent` | 消费者 → 订阅的生产者 + gossip | 找不到时才广播的签名求购 |
| 交易流程 | 沿用 v0.1 | 询价/报价/还价 → AP2 授权链 → 托管 → 物流签收 / 内容哈希校验 → 结算与分账 → 评价 |

## 快速开始

```bash
pip install -e ".[dev]"
pytest                                                   # 41 个测试
python -m agora.sim.run                                  # 43 个智能体，各自一个 HTTP 服务，12 轮，约 30–50 秒
python -m agora.sim.run --transport memory --seeds 5     # 5 个随机种子，均值 ± 标准差
python -m agora.sim.run --transport memory --seeds 5 --no-producer-learning   # 对照：生产者不从反馈学习
bash scripts/fetch_upstream.sh                           # 拉取 X 开源代码与 A2A / AP2 规范
```

**改用大模型做决策脑**（例如 AutoDL 上的 vLLM；Qwen3 的 `<think>` 思考段会被自动剥掉）：

```bash
vllm serve Qwen/Qwen3-8B --port 8000                     # 在 GPU 机器上
export AGORA_LLM_BASE_URL=http://<host>:8000/v1 AGORA_LLM_MODEL=Qwen/Qwen3-8B
python -m agora.sim.run --llm --consumers 6 --rounds 4   # 规模先调小：每个智能体每轮都要调用大模型
```

大模型每一步要么调用技能（`{"call": ...}`），要么给出决策（`{"decisions": [...]}`）。每条决策都要在代码里再过一道闸：用户的硬性规则（屏蔽、标注方判定、讨厌的品类、发货地区、信任下限）对大模型同样生效，购买只能针对未满足的需求且不超预算，展示不超过注意力额度；生产者的大模型只能向手里有兴趣卡或求购的智能体提议，并受对方每日上限约束。不合规的决策直接丢弃并计数；模型漏掉的条目由规则补上；模型输出乱码则整体回退到规则。所以 Offer 里的文字即使诱导了模型（提示词注入），也越不过用户设的边界。

用户还可以直接用一句话设置画像：`UserProfile.from_text("我喜欢科幻小说和咖啡，不想看体育，需要一双70美元以内的越野跑鞋")`；配置了大模型时用 `llm.profile_from_text`。

## 仿真结果（合成经济：只能说明机制能跑通，不代表真实市场效果）

每个模拟用户有隐藏的真实偏好，只告诉自己的智能体一部分：4 个喜欢、2 个讨厌、价格上限。每个生产者有隐藏的真实质量。另外混入两个坏人：一个卖假货并给所有人群发的商家，一个付费内容货不对版的作者。24 个消费者智能体中，一半注册了 X 技能，一半只有基础技能，在同一个网络里对比。

**5 个随机种子（7–11）均值（标准差）：**

| 指标 | 带 X 技能 | 只有基础技能 |
|---|---|---|
| 展示内容的真实相关度 | 0.533 (0.022) | 0.505 (0.023) |
| 用户喜欢的比例 | 0.654 (0.031) | 0.617 (0.057) |
| 展示内容中骗局的占比 | 3.7% | 5.9% |
| 需求满足率 | 0.86 (0.11) | 0.80 (0.03) |
| 人均成交 | 4.5 | 3.3 |
| 人均消费者剩余（美元） | 39.0 (19.1) | 24.6 (9.0) |

| 网络整体 | 数值 |
|---|---|
| 付给坏人的钱 | **5 个种子都是 0**，货款全部守恒 |
| 群发垃圾的商家 | 推送接受率 6.5%，平均被 24 个智能体中的 13.8 个屏蔽，零成交 |
| 诚实生产者的推送接受率 | 72%（关掉反馈学习后为 71%，见下） |
| 用户没提过的品类，学到的排序与真实偏好的 Spearman | 0.30 (0.09)；只靠用户自述时为 0 |
| 隐私披露 vs 结果 | 公开卡：每人收 44 条推送、需求满足 0.86；仅订阅者：24 条、0.81；私密：14 条、0.80（私密组每个种子只有约 3 人，样本小） |
| 拒绝理由的分布 | unsafe 631、off-topic 198、attention-budget 153、too-expensive 67、not-shippable 65、disliked-category 35 |

另有真实 HTTP 运行（`runs/agent-net-http-seed7/`）：43 个服务器、12 轮、46 秒，成交 97 笔、退款 9 笔（全部来自两个坏人），付给坏人 0 元，共 5035 条 A2A 消息。HTTP 下消息到达顺序不固定，会改变随机数的消耗顺序，同一种子重复运行的成交数在 87–97 笔之间；内存传输下结果可完全复现。

**需要直说的几点：**
- **X 技能的作用**：带来的是**小幅**提升（相关度 +5%、喜欢率 +6%）。成交数和消费者剩余的提升更大，但方差也大。由于资格判断始终来自用户画像，X 只负责排先后，影响有限，这是有意的设计。
- **生产者从反馈中学习**：在这个仿真里**没有带来可测的提升**（接受率 72.3% 对 71.4%）。兴趣卡已经提供了大部分定向信息。这项能力要在兴趣卡粗糙、缺失或有误时才可能有价值，目前未验证。
- **探索的代价**：探索能学到用户没说过的兴趣，但会拉低当轮的展示精度。整体偏好排序（Spearman 0.88）略低于只用用户自述的 0.90，因为少量反应会给已知喜好带来噪声。
- 结果全部来自合成数据。

## 局限

- **受信第三方**：支付清算和托管仍然是受信第三方，仿真里只有一家银行。去掉的是撮合与定价的垄断，不是清算本身。
- **隐私**：结算记录经 gossip 公开；公开兴趣卡虽然做了粗化，仍会暴露部分偏好。选择性披露（SD-JWT）是下一步。
- **大模型决策脑**：只用模拟服务器测试过协议、代码闸和回退逻辑，**没有用真实大模型跑过仿真**，效果未知。
- **好友关系**：仿真里加好友请求自动接受；实际部署应由用户确认。
- **发现层**：目前是引导节点加 gossip，规模化需要 DHT 或中继。
- **A2A 未实现部分**：gRPC 绑定、推送通知、`securitySchemes`。所有涉及钱和反馈的请求都改用请求体签名。
